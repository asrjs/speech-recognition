## 2026-05-25 - [Optimize Audio Post-Processing Arrays]
**Learning:** In audio post-processing mapping loops (e.g., `lasr-ctc/mapping.ts`, `nemo-common/mapping.ts`), executing nested `.filter(...).map(...)` chains to find matching `tokenIndices` for every word creates severe GC pressure due to multiple intermediate array allocations per word. Note that the direct for-loop replacement only resolves the intermediate array allocations; the loop itself remains $O(N \times M)$ unless refactored with a two-pointer approach or similar.
**Action:** Use a single-pass `for` loop over the tokens array to populate a local `tokenIndices` array directly, which has been shown to improve performance significantly (by approximately 35-40% in large segment processing) by eliminating intermediate allocations.
