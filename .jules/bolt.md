## 2024-06-25 - O(1) Lookups in Static Model Catalogs
**Learning:** In static model catalogs (like `canary/catalog.ts` and `parakeet/catalog.ts`), lookups by `repoId` use O(N) linear scans with `Object.entries()` or `Object.values()`. Repeated allocations from these methods combined with linear searches are inefficient, especially as model counts grow. Similarly, `supportsLanguage` uses an O(N) `array.includes()` which can be replaced with an O(1) `Set` lookup.
**Action:** Always pre-compute static O(1) reverse mappings (e.g., `REPO_ID_TO_KEY`) for key/repoId resolution to avoid `Object.entries()` allocation overhead and linear searches. For frequent language membership checks, cache `Set<string>` objects using a `WeakMap<Config, Set<string>>` for O(1) average lookup performance.
